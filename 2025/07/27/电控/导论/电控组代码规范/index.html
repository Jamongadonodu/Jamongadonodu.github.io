命名规则

类型 规范 示例
变量 小写下划线 present_value
枚举量 全大写 KEY_UP
常量，宏 全大写 #define PWM_MAX const uint8_t ID
结构体类型 小写下划线+后缀(_s) struct motor_data_s{ }
枚举类型 小写下划线+后缀(_e) enum motor_mode_e{ }
自定义类型 小写下划线+后缀(_t) typedef struct { } motor_mode_t

在定义几个相关的常量时，最好用枚举。

说明 ：

  1. 命名规则
  • 变量名应当反映出变量的用途或内容，避免使用无意义的名称。
  • 禁止出现拼音。请使用简介明了的英文
  • 减少使用缩写命名，除非像“temp”（temporary,常用于表示临时变量）一样非常通用且容易理解,缩写也要小写
  • 好的代码是不解自明的：通过变量名即可明白该变量的作用。必要时添加注释辅助说明。
  1. 同一模块的变量，使用结构体封装管理 如motor_data_t
  2. 特定模块的变量，封装在函数内部，定义为函数内部变量，文件内部变量均标为static
  3. 在项目或代码库中，应保持命名风格的一致性，以便于维护和理解。

函数规则

  1. 函数以名词 + 动词命名,或是模块名 + 动词 + 名词，且以小写下划线的规则书写
  • 如‘motor_init’ ‘i2c_read_data’
  1. 函数应该简短而漂亮，并且只做一件事情，而且把它做好。
  2. 一个函数的最大长度是和该函数的复杂度和缩进级数成反比的。所以，如果你有一个理 论上很简单的只有一个很长 (但是简单) 的 case 语句的函数，而且你需要在每个 case 里做很多很小的事情，这样的函数尽管很长，但也是可以的。
  3. 函数的另外一个衡量标准是本地变量的数量。此数量不应超过 5－10 个，否则你的函数就有问题了。
  4. 文件内部调用的函数均标为static，外部调用的函数在头文件中声明

文件的命名格式

  • 对于所有的文件夹统一使用第一个字母大写的方案，例如：Bsp、Hardware、Control，Src，Inc

  • 对于所有的.c和.h文件则是使用全小写方案，例如：led.c、led.h

  • 对于使用分层架构设计的文件，加上该文件对应的前缀，例如drv_can.c,dev_oled

编码格式

统一使用UTF-8编码，严禁使用GBK或GB2312！！！

宏

宏的名字请用大写字母，不过形如函数的宏的名字可以用小写字母。
一般的，如果能写成内联函数就不要写成像函数的宏。
含有多个语句的宏应该被包含在一个 do-while{0} 代码块里：

内联（C语言并不常用）

有一个常见的误解是 内联 是 gcc 提供的可以让代码运行更快的一个选项。虽然使用内联函数有时候是恰当的 (比如作为一种替代宏的方式，请看第十二章)，不过很多情况下不是这样。inline 的过度使用会使内核变大，从而使整个系统运行速度变慢。

总之，

一个基本的原则：内联函数通常不超过三行

条件编译

  1. 只要可能，就不要在 .c 文件里面使用预处理条件 (#if, #ifdef)；这样做让代码更难 阅读并且更难去跟踪逻辑。

  2. 最好倾向于编译整个函数，而不是函数的一部分或表达式的一部分。与其放一个 ifdef 在表达式内，不如分解出部分或全部表达式，放进一个单独的辅助函数，并应用预处理 条件到这个辅助函数内。（集中处理）

头文件保护一定要写

  • 对于整个文件的注释，我们希望

原则：

  1. 注释是好的，不过有过度注释的危险。永远不要在注释里解释你的代码是如何运作的： 更好的做法是让别人一看你的代码就可以明白，解释写的很差的代码是浪费时间。

  2. 一般的，你想要你的注释告诉别人你的代码做了什么，而不是怎么做的。也请你尽量不要把注释放在一个函数体内部：如果函数复杂到你需要独立的注释其中的一部分（点名批评逐行注释），那么你的函数不符合函数规则

  3. 你应该做的，是把注释放在函数的头部，告诉人们它做了什么，也可以加上它做这些事情的原因。

代码风格（不做强制要求）

代码风格的意义就在于使用平常使用的工具来维持代码的可读性和可维护性。

但介于每个人都有自己的代码风格，这个部分不会硬性要求统一，但还是推荐使用以下代码风格

缩进

制表符是 4 个字符，所以缩进也是 4 个字符。
理由：缩进的全部意义就在于清楚的定义一个控制块起止于何处。尤其是当你盯着你的 屏幕连续看了 20 小时之后，你将会发现大一点的缩进会使你更容易分辨缩进。

把长的行和字符串打散

每一行的长度的限制是 80 列，我们强烈建议您遵守这个惯例。

空格的使用

  1. 关键字后加空格
    在这些关键字后面加空格：

if, switch, case, for, do, while

但是这些不加：

sizeof, typeof, alignof, attribute

  1. 括号内，紧挨着括号不加空格

  2. 对于指针，”*“号挨着名字而不是类型

  3. 操作符两侧加空格
    以下二元或三元操作符两侧要加空格：

= + - < > * / % | & ^ <= >= == != ? :

但是以下一元操作符，不加空格：

& * + - ~ ! sizeof typeof alignof attribute defined

自增自减符号。不加空格：

++ –

结构体成员操作符，不加空格：

‘.’ 和 “->”

不要在行尾加空格。
